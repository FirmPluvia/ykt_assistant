# Cookie 复制与登录

Cookie 管理和 Cookie 登录使用两个独立卡片与弹窗，不根据登录状态复用同一表单。

## Cookie 管理

已登录时：“我的 → 请求设置 → 管理 Cookie”。只展示当前服务器、当前账号的只读 Cookie，以及复制和关闭按钮。复制不发请求、不切换账号、不改写会话，不提供登录操作。

## Cookie 登录

未登录时可通过独立 Cookie 登录卡片，或二维码卡片底部“Cookie 登录”进入。已有账号可先在账号管理中点击“添加账号”。登录卡片只有服务器、空白输入框、登录和取消，没有复制或保存按钮。

每次打开输入框始终为空，切换服务器也清空；添加账号时不会加载当前账号 Cookie、其他已保存账号或旧版草稿。用户主动粘贴 `sessionid=...; csrftoken=...; sid=...`，支持 `Cookie:` 前缀，不接受 Set-Cookie 响应头、完整 HTTP 报文或换行注入。

校验使用独立临时会话和设置的 User-Agent 请求个人信息，成功后保存活动会话和账号记录。失败或取消不接受新账号；添加流程取消后可恢复原账号。Cookie 请求头不含有效期属性，实际有效期由服务端决定，应用重启仍请求个人信息确认状态。

## 保存与退出

活动 Cookie 仍自动明文保存于 `/data/user/0/<包名>/shared_prefs/native_session.xml` 的 cookies 字段，服务端 Set-Cookie 会更新它。复制按钮不改变这一登录缓存机制。旧 encrypted 数据兼容解密迁移一次后删除旧字段；新会话不进行 Cookie 加密写入。系统备份和设备迁移继续禁用。

退出登录清除当前账号 Cookie、其保存的账号记录和旧版 native_cookie_settings 草稿，其他已保存账号仍保留；撤销旧活动会话写入权限。课堂凭证永久保留，仍按服务器 / 账号 / 课堂隔离并加密；动态缓存仍在退出时清理。密码、短信码不保存。

## 界面

设置页不再展示“连接方式”内容。课程卡片的“查看课堂”为主要操作，“复制课堂 ID”固定在操作栏左侧，保持较小字体与至少 44dp 的触控区域。

各已验证账号的 Cookie 还会按服务器 / user_id 保存于内部私有 saved_accounts.xml，供手动切换或所选账号签到使用；均为明文，不保存密码。添加账号、默认全选和串行签到、取消恢复流程见[多账号](multiple-accounts.md)。
