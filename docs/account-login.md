# 账号密码、短信登录与腾讯验证（3.2）

本模块根据已确认的协议字段和前述功能要求重新编写，无需旧 29 版源码。保留二维码登录，原生登录窗口支持切换“账号密码”“短信验证码”和雨课堂服务器。

## 请求顺序

- 手机号密码使用 type=1，邮箱密码使用 type=2，POST `/api/v3/user/login/app`；密码不 trim，只通过所选雨课堂 HTTPS 接口提交。
- 短信发送先由用户手动完成腾讯验证，再 POST `/api/v3/user/code/send`；发送成功后按服务器 / 手机号冷却 60 秒。
- 输入短信码后先 POST `/api/v3/user/code/verify`，校验成功再以 type=3 POST `/api/v3/user/login/app`，最后 GET `/v/course_meta/user_info` 验证账号资料。
- type、phoneNumber、email、password、code、pushDeviceId、ticket、rand 均按模式设置，不适用字段为空。pushDeviceId 为本次客户端随机 UUID，不读取硬件标识。
- 短信验证码错误时不继续调用登录；资料无有效 user_id 时不接受登录。

## 隔离与隐私

每次切换服务或登录方式都会撤销旧客户端、清空密码 / 短信码与人机验证票据。关闭窗口、退出账号后拒绝旧挑战和网络结果。短信凭据只能用于本次同一手机号与服务器，不能换号复用。

账号与验证码输入框不保存实例状态、禁用自动填充；密码 / 验证码只在原生内存使用，不放进 SharedPreferences、日志或验证 HTML。成功登录的 Cookie 沿用 SessionVault 的 Keystore 加密保存。

## 腾讯验证显示

用户手动完成腾讯官方组件，公开 AppId 为 2091064951，脚本 `https://turing.captcha.qcloud.com/TCaptcha.js`。仅验证组件使用受限 WebView，账号密码、短信码、雨课堂 Cookie 不注入网页；只有 ticket / randstr 返回原生层，不自动求解或绕过验证。

验证使用非浮动全屏容器，取消 640 物理像素上限与半屏高度。WebView 占据原生标题栏以下完整区域，网页 margin / padding 为 0，由腾讯组件自行居中，避免高密度屏裁切。适配系统栏、刘海和窗口尺寸变化，打开时隐藏原生输入法。

禁用文件 / Content 访问、混合内容、多窗口；只放行官方验证码 HTTPS 域名及必要内联资源。回调只接受有限长度的票据。取消 / 关闭后销毁 WebView，回调最多一次。日志 HUMAN 阶段只标注请求、完成、失败或取消，不保存票据。

## 验证范围

回归覆盖手机号 / 邮箱类型、字段、Cookie、校验顺序、冷却、关闭后拒绝回调、换号 / 换服务、密码重试、二维码往返，以及高密度与小屏宿主布局。采用模拟接口和人工验证回调；真实四个服务的短信下发、设备 WebView 与腾讯策略仍需真机验证，没有使用真实账号或自动发送真实短信。
