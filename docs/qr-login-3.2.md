# 二维码登录与诊断（3.2）

二维码接口仍为所选雨课堂服务器的 GET `/api/v3/user/login/pre-info` 和 POST `/api/v3/user/login`，成功授权后 GET `/v/course_meta/user_info` 校验用户资料。未修改二维码内容为 token；优先按官方 `qrContent` 本地绘码，缺失时加载同一响应的 `qrImage`。

## 轮次与有效状态

- 每轮使用独立客户端、CookieJar、token 和二维码图片，日志用独立随机轮次 ID 关联，不把 token、用户 ID、Cookie 值或其哈希写入日志。
- 手动刷新与切换服务立即撤下旧码，再取消旧请求。旧轮次结果、图片、Cookie 写入不能激活新轮次。
- 当前二维码显示后开始长等待；收到 50001、网络超时或连接失败时先撤下旧图片，明确显示旧码不可继续扫描。
- 正常长等待结束后自动获取新轮次；异常连续快速失败使用 2、4、8、15 秒等退避，最多连续失败五次后等待手动刷新，防止请求风暴。手动刷新保留二次确认。
- 关闭窗口、切换服务和退出应用会取消当前请求及后续轮询；不会在关闭窗口后接受迟到登录结果。

## 授权与资料分开恢复

扫码授权成功后立即隐藏二维码，再用本轮 Cookie 获取资料。用户资料请求失败会重试三次，期间保留已授权会话；仍失败时显示“重试获取账号信息”，不会自动清空有效 Cookie 或强迫重新扫码。资料校验成功后才接受登录和保存账号状态。

## 诊断日志

文件：`Android/data/<包名>/files/logs/yyyy-MM-dd/app.log`，外部应用目录不可用时使用内部私有目录。每天约 1 MiB 轮换一次，保留当前及前一份日志，自动清理约 7 天前的日志。

“我的 → 诊断日志 → 导出今日日志”通过系统文件保存器导出；不会自动上传。

记录内容：时间、3.2 / 构建号、轮次 ID、所选公共服务器、请求阶段、HTTP / 业务错误码、耗时、是否存在 session / CSRF Cookie、二维码来源。只允许预定义标签与随机轮次 ID；不记录请求 / 响应正文、二维码内容、token、Cookie 值、密码、短信验证码、头像或用户标识。

阶段：QR_FETCH 获取二维码，QR_WAIT 等待授权，QR_AUTH 授权与接受登录，PROFILE 获取资料，QR_SESSION 本轮 Cookie 存在性，UPDATE 更新检测。

- QR_WAIT 的 50001：服务端结束本轮扫码等待，旧码被撤下后会自动重取。
- QR_WAIT 401 / 403：授权等待请求被拒绝，应结合本轮 Cookie 存在性及服务版本分析。
- PROFILE 失败而 QR_AUTH 为 AUTHORIZED：扫码已授权，应重试资料而非重复扫码。
- UPDATE 失败后 EXIT_TO_PROJECT：更新检测按旧逻辑触发退出，会同时终止二维码等待。

Cookie 存在性按实际接口 URL 记录，不假设所有 Cookie 都适用于根路径；存在不等于有效，也不是接口一定需要 Cookie 的证明。微信公众号提示的失败属于另一端，客户端日志只能辅助关联，不能直接替代微信 / 服务端回调证据。
