# 多账号与所选账号入课

## 添加、切换与退出

入口：“我的 → 账号管理”。成功登录的账号自动保存，旧单账号版本在首次恢复并校验个人信息后加入列表。支持标准 / 荷塘 / 长江 / 黄河服务，同一 user_id 在不同服务器属于不同账号记录。

添加账号会先保存当前会话，再打开原二维码 / 密码 / 验证码 / Cookie 登录流程。取消添加时，使用原保存会话校验并恢复；若恢复失败，原记录仍在，可在账号管理中重试。添加中断时，重启可回退至先前已接受的活动账号，临时扫码 Cookie 不作为已登录账号保存。

切换先独立校验保存的 Cookie，检查返回 user_id 与该记录一致，成功后才替换活动会话。失败或取消不会切换当前账号或服务器。保存的 Cookie 过期时需要重新添加 / 登录该账号。重复登录同服务器同 user_id 更新现有记录，不增加重复项。

退出当前账号会移除其保存的 Cookie 记录，其他账号保留；移除其他保存账号只删除该账号的 Cookie 与资料，不自动删除永久课堂凭证。账号切换时关闭旧连接、隔离迟到回调；当前界面与动态缓存重新按活动账号建立，不混用课堂凭证。

## 所选账号签到入课

多个账号时，入课确认弹窗和实时课堂课件页提供“同步签到”复选框和“修改账号”操作。仅列出同一雨课堂服务器的其他保存账号，首次打开默认全部勾选。用户确认修改后（包括全部取消），再次打开保留原选择；取消弹窗不改变选择。

- 在当前账号入课确认中选择后，仍需点击“签到并进入课堂”；当前账号成功后才处理所选其他账号，当前账号失败则不发送其他账号签到。
- 已在实时课堂时可直接选择其他账号，不重复提交当前账号签到。
- 对每个所选账号分别创建客户端，用其 Cookie 请求个人信息并核对 user_id；使用它自己的 HTTP / WebSocket 课堂凭证，绝不复用当前账号的凭证。
- 按列表顺序逐个处理，前一账号的个人资料校验、签到响应、凭证保存及客户端关闭全部完成后，才创建下一账号的请求，不并发发起多个账号签到。已有匹配本机凭证时复用，状态显示“已复用本机课堂凭证”，不把它当成服务端新签到确认；没有凭证时请求原 checkin 接口，成功后保存该账号的凭证。
- 不为其他账号建立课件 WebSocket 或更改当前账号 / 课件。逐个展示成功、复用或失败；某账号失败不抹去其他账号的成功结果。
- 取消会中断当前连接并停止后续账号，已到达服务端的签到无法撤销。特殊动态二维码、位置签到、课程权限等要求仍由服务端处理，本功能不代替这些验证。

## 动态中的实时课件

动态课堂记录若与首页正在上课列表匹配、已在当前实时课堂，或课堂报告表明已开始且未结束，则检查当前账号的本地课堂凭证。命中后用 WebSocket hello 获取当前 presentation ID，再调用 `/api/v3/lesson/presentation/fetch?presentation_id=...` 并携带该账号的课堂 Bearer，显示实时课件。

没有凭证时保留课堂报告和原版历史课件入口，提供“进入实时课堂”按钮供明确确认签到，不为浏览动态自动签到。未显示课件时继续显示等待 / 连接状态，不把历史回顾当实时课件。凭证读取期间返回或切换页面，会取消迟到的页面跳转。

## 存储与验证

账号资料及 Cookie 明文保存在内部私有 `shared_prefs/saved_accounts.xml`，按服务器和 user_id 区分。活动会话同时写入原 native_session.xml；服务端 Set-Cookie 更新对应账号。移除账号会撤销其保存 Cookie 的写入租约，旧请求不能重新创建该记录。密码、短信验证码、腾讯验证票据不保存，不生成诊断文件。

课堂凭证继续独立加密并永久保留，作用域为服务器 / 账号 / 课堂；动态缓存切换时撤销旧作用域。测试使用模拟 HTTP / WebSocket，不代表真实学校权限或真实账号联调已完成。

## 同步答题

各目标账号需已有本堂课凭证。配置范围和使用方法见[同步请求](request-sync.md)。
