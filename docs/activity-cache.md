# 动态数据缓存（2.9.0）

## 保存内容与隔离

在已登录账号下缓存动态列表、分页游标、课堂信息 / 签到详情，以及已获取的原版课件页信息。记录按服务器域名、账号 ID 和注销代次隔离，优先保存到 Android/data/com.ykt.assistant/files/activities/ 下的加密文件。

使用独立 Android Keystore AES-GCM 密钥，作用域作为认证附加数据；账号信息和图片签名链接不会以明文写入文件。退出账号立即撤销旧会话读写权限，并后台删除旧代次文件。不会重新启用已删除的日志功能。系统未提供外部应用专属目录时使用内部私有目录，备份策略沿用应用的禁用配置。

只缓存 API 数据与课件页面信息；此缓存不等于把全部课件图片原文件下载到磁盘。图片仍使用现有内存缓存与下载功能。

## 首屏与分页连贯性

1. 进入动态先读取已验证登录账号对应的缓存，默认仅显示最新 10 条，随后仍正常 POST activities/received/ 获取最新 10 条。底部导航进入和手动刷新都会检查首屏；从详情返回列表保留原位置，不额外请求同一首屏。
2. 将新首屏与缓存比较。重合记录采用新响应的字段；在新首屏已覆盖的范围内移除消失记录，保留更早的缓存历史。
3. 用稳定记录身份、创建时间和原始 sort 共同确认衔接点。仅仅同一课程 / 动态 ID 被更新并移动到顶部，不作为连续性证据，避免误删中间记录。
4. 有衔接时复用本地更早页面与其原始末尾游标，不重拉已缓存的中间页。首屏只显示 10 条；点击“加载更多动态”先展开全部连续缓存，不发送分页请求。展开后再次点击才按末尾游标请求下 10 条。没有更多本地缓存时直接请求下一页。刷新动态或再次点击底部动态入口会恢复首屏 10 条；从详情返回则保留展开状态和位置。
5. 没有衔接时，旧片段仍保存在磁盘，但先只展示已确认连续的新片段。“加载更多”沿新的 searchAfter 补齐缺口，重合后接上旧片段；不直接跨过缺口使用旧游标。
6. 多次刷新产生的片段也会保存并恢复。空首屏视为当前服务端确实无动态，清除旧列表；缺少 / 重复游标时停止，刷新可重新建立有效分页。

游标始终使用服务器原始响应末条记录的 sort 字符串，保留空格与内容，不根据去重后列表重建，也不把它转成数组发送。首屏检查失败时保留已经读取的缓存。

## 详情与课件请求复用

- 已结束课堂、成功完整取得的签到 / 课堂详情优先长期复用，首屏对应记录变化或点击“刷新记录”后更新。
- 未结束 / 待确认或信息不完整的记录按约 1 分钟的有效期按需更新；已经成功得到的详情会尽量复用，只补缺失字段。失败不是最终签到状态，也不会永久缓存成未签到。
- 同一课堂的列表元数据加载与详情页共用进行中的请求，离开页面后成功返回的数据也可保存，不为再次打开重复发起相同请求。
- 原版课件页信息缓存约 30 分钟，以免长期复用可能过期的签名地址。“刷新课件”始终绕过缓存；如果图片地址提前失效，可使用该按钮重新获取。
- 服务端若仅修改更早课堂的签到或课件、而首屏活动字段未变化，不能仅凭前 10 条检测该修改，可在对应详情使用“刷新记录”。

首页入课仍只检查课堂凭证缓存，动态报告缓存不会成为入课或签到的前置条件。

## 文件写入与恢复

比较规范化 JSON，忽略对象键顺序；列表、必要游标或元数据变化才写入，单纯首屏检查时间不会造成重复写入。多次元数据更新合并写入，磁盘 I/O 在独立后台队列执行，使用 AtomicFile 防止半文件覆盖。

页面停止 / 退出时会提交待保存的快照。损坏、认证校验失败或不支持的缓存会忽略，正常重新请求。单个快照限制约 16 MiB，写入失败时不破坏上一次有效快照，也不阻断动态查看。

## 验证范围

测试覆盖首屏重合 / 删除 / 重排、新旧片段断开与补齐、重复游标恢复、跨重启序列化、相同数据不重复写、加密与账号 / 服务器隔离、注销拒绝迟到写入、原子备份恢复、首屏失败保留缓存，以及列表 / 详情共用请求和原版课件信息复用。

测试使用模拟接口与测试密钥；真机 Keystore、文件权限和服务器数据变化仍需实际设备确认。账号登录恢复仍沿用现有流程，不额外保存明文账号资料。
