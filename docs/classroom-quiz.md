# 课堂题目与手动作答

进入实时课堂后，在课件下方点击“课堂答题”。题目来自课堂课件 `slides[].problem`，开放状态和时间来自同一课堂 WebSocket 的 `unlockproblem` / `timeline`。题目列表可切换，草稿按题目分别保留，不随翻页互相覆盖。尚未开放的课件题目只读。

## 支持的作答方式

| 原始编号 | 支持方式 |
| --- | --- |
| 1 | 单选，提交 `options[].key` 数组 |
| 2 | 多选，按原选项顺序提交 key 数组 |
| 3 | 投票，按 `pollingCount` 限制选择数量；缺失时按单选处理 |
| 4 | 填空，按 `blanks` 返回的数组顺序提交，不按 num 重新排序 |
| 5 | 主观题文字或图片，提交 content、pics 和空 videos 数组 |
| 6 | 判断题：选择一个接口原始 key，result 为单项字符串数组；未知类型仍只读 |

题干和选项支持 HTML 文字格式；可打开关联课件图片并缩放查看图片中的公式 / 图形。主观题支持系统选择器选图上传（最多 6 张）与纯图片答案，视频暂不支持；不申请相册全量读取权限，不显示服务端可能附带的正确答案或解析。

## 时间与补交

题目开放事件保存原始毫秒时间 dt。收到带 limit 的题目时，按事件时间估算剩余时限，再使用 Android 单调时钟计时；返回前台按当前时钟更新，不靠每秒减一累积计时。重复收到同一时间线不会重启倒计时或清空草稿。缺少 limit 时明确显示时限未提供。

`extendtime` 优先按明确的 prob 匹配题目，缺失时关联当前最后开放题目；增加剩余时间，已超时时从零增加。带 dt 的重复延时事件去重；协议未提供可去重标识的事件按每次收到处理。

正常作答发送 `POST /api/v3/lesson/problem/answer`，dt 为当前时间。答题时限结束或收到下课事件后，按钮改为“补交答案”；二次确认后请求 `POST /api/v3/lesson/problem/retry`。补交使用原始题目事件 dt，`problems` 数组包装单题并带 JSON null 的 `retry_times`。缺少原始时间时禁用补交，不生成猜测时间。

倒计时、事件和切换题目都不会自动提交。补交是否接受、是否计分由雨课堂决定。当前未提供官方历史作答状态查询，因此“本机已提交成功”只表示本次客户端收到明确 code:0，不代表答案正确或记录已与其他设备同步。

## 账号、课堂与失败处理

“提交答案”先处理当前账号；多账号启用“同步答题”后，会继续处理所选同服务器账号，AI 分析页提交相同。详见 [同步请求](request-sync.md)。各账号使用自己的凭证，不自动签到。题目详情与提交均绑定当前课堂，携带此账号 Cookie 和课堂 Bearer，不重复入课。根据题目自身 problemId 查找详情，不根据时间线 si 猜测下标。

旧课件题目可根据该课堂时间线的 pres 单独获取，不改变当前阅读课件。切换账号 / 课堂、退出和销毁会关闭答题面板、丢弃该课堂草稿与旧回调；同一课堂内关闭面板 / 导航 / 返回前台不清除草稿。草稿只在内存保存，进程结束后不恢复，不写入日志或磁盘。

每道题提交期间禁用输入和提交，成功后禁止本机重复提交。明确失败时保留草稿，显示错误；网络中断可能发生在服务端已接受之后，此时提示先核对官方记录，不自动补发或切换接口。提交请求禁用自动连接重试。新开放轮次只重置该题草稿，旧轮次请求的返回不会覆盖新题。

## 验证范围

测试覆盖题型序列化、选项数量 / key 校验、单调计时、重复时间线、延时、缺失时间、补交确认、重复点击、失败保留、题目新轮次、课堂和账号隔离、HTTP 鉴权 / 响应校验、旧课件获取与原生 UI。全部使用本地模拟接口，没有在真实课堂代用户提交，真机兼容性与学校端补交规则仍需实际验证。

## AI 答题辅助

可在题目中请求 AI 分析，校验 JSON 后预览或自动填入本题草稿，提交仍由用户手动触发。接口、模型与 Key 在“我的”配置，详见 [AI 答题辅助](ai-quiz.md)。
